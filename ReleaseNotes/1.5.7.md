# 1.5.7

修复 SDK 缓存读写过程中，部分临时响应对象延迟释放导致的竞态崩溃。本次属于局部修复：缓存查询及 304 更新返回对象在调用方释放、其他组件共同访问系统共享缓存等场景仍存在残留风险。并发验证中仍观察到 SDK 缓存查询路径异常，现有数据不能量化现网崩溃率降幅。

修复异常或超大 `NSURLRequest.timeoutInterval` 值转换为 libcurl 空闲超时时可能引发的误超时。归一化规则如下：

| 输入值 | SDK 配置的 libcurl 空闲超时 |
| --- | --- |
| `NaN`、零或负数 | 不启用此项空闲超时 |
| 大于零且不超过 86400 秒 | 按秒向上取整，例如 `0.3 → 1`、`1.2 → 2` |
| 超过 86400 秒的有限值，或正无穷 `INFINITY` | 限制为 86400 秒（24 小时） |

**兼容性变化：** 大于 24 小时的正有限配置现在会被截断到 24 小时，`INFINITY` 也会按 24 小时配置；正小数按秒向上取整。依赖这些取值的接入方应在升级前评估其空闲等待要求。这些规则仅决定 libcurl 空闲超时，NSURLSession 和连接超时仍按各自配置生效。

新增的 5 个缓存功能回归在 iOS 26.5 模拟器及 iOS 18.5 真机均通过。并发验证的结果与归因限制见 [缓存验证记录](../EMASCurlTests/CacheValidationResults.md)。
